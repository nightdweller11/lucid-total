Secure storage and transport for API keys and the like through the chat and the app in dedicated windows. Use Lucid Chat's theming; must work well on a PC and on mobile; testing included and properly executed. → `docs/00` principles 2, 9, 11; `docs/06`; `docs/07` §5; `docs/09`; `docs/research/`.

APIs into all the organisation's systems, replacing many. ## 2026-10-28 · Lead decisions (pending the owner's confirmation)

- **T9 (lead).** Documentation order and set as in `docs/00` §7–§8; the methodology of Lucid Chat (walkthroughs, docs in the same change, lead orchestrates, Opus workers, Fable for core and security work, Railway-first, current majors, no GitHub Actions) is inherited verbatim.
- **T10 (lead).** Stack: TypeScript 6 / Node 22, Fastify 5, Drizzle + Postgres 18 on Railway, React 19 + Vite, SVG map with server-computed scenes, in-memory hybrid retrieval with a local embedding model, the Claude API through `packages/ai-gateway` (the official TypeScript SDK inside the adapter only), Railway Buckets. No Redis, NATS, vector DB or Kubernetes at the start (`docs/05` §2, §12).
- **T11 (lead).** Secrets travel as end-to-end encrypted envelopes sealed in the browser to recipients' keys; the server stores ciphertext only; the model never sees envelope contents (`docs/07` §5).
- **T12 (lead).** The autonomy ladder (observe · suggest · confirm · inform · run) is a setting per process; defaults for Lucid in `docs/02` §2.7; outbound channels off until enabled, each with a kill-switch.
- **T13 (lead).** The owner's inbox follows Lucid Chat's L425 rule: material decisions only, one at a time, full context and cost in plain words; small things are settings; very small ones the lead decides and logs here.
- **T14 (lead).** Phase order: Phase 0 the board and the coordinator protocol (the checklist replaced), Phase 1 the AI runs the operation, Phase 2 the map and decisions, Phase 3 company-wide, Phase 4 product (`docs/11`).
- **T15 (lead).** Workload signals about people (T5's "these employees aren't doing well") are implemented as explainable work signals shown to the person first and to the role holder as a workload concern, with thresholds as settings and no verdicts about people (UC-E4). Rationale: trust, labour-law exposure in several markets, and the owner's stated goal of helping the work move.
- **T16 (lead).** Model classes `fast` / `standard` / `strongest` / `fable` map to `claude-haiku-5-5` / `claude-sonnet-5-5` / `claude-opus-5-5` / `claude-fable-5-1` in configuration (2026-10 ids); the owner's chat defaults to `strongest`; Fable is enabled per company by the owner.

- **T18 (lead).** Asks are one kind (`ask`) with routing rules and a decision outcome, and proposals (T7) are asks that target a decision; one inbox, one ageing rule (`docs/02` §4.9).
- **T19 (lead).** Externals are **parties** with **engagements** and **compartments**, in three modes sharing one identity (direct, virtual, system); compartments are enforced at the data layer and by the retrieval and tool filters; engagement end dates revoke access automatically (`docs/02` §4.10, `docs/07` §3b).
- **T20 (lead).** Payroll-class data gets its own sensitivity class with server-side field-level encryption (not end-to-end, because cleared staff and payroll connectors must process it), read audit and an integrity-chained audit log; end-to-end envelopes remain the mechanism for secrets (`docs/07` §6b).
- **T21 (lead).** Company stage is a setting with four values whose change is proposed by the system and decided by the owner with a preview; Lucid runs at `founders` (`docs/02` §2.8).
- **T22 (lead).** Phasing: asks v0 and `founders` defaults in Phase 0; virtual parties in Phase 1; direct external views, compartments and the admission gate in Phase 2; payroll-class data, the board compartment, the stage model and the pen-test gate in Phase 3 (`docs/11`).

- **T23 (lead, import rules).** Answers to the importer's questions (`docs/10` §7): (1) the 257 orphan follow-ups stay linked to their wave grouping with `origin_unresolved: true`; the review wave LT-0005 attaches them with the AI's proposals; (2) "lead decision pending" entries dated on or before 2026-10-24 are closed as a group under Lucid Chat's L425 and are not shown to the owner again; (3) a done row that cites only an existing code or doc file keeps evidence grade 2 but is sub-labelled `file`, and the "to verify" set stays grades 0–1 plus missing walkthroughs and stale blockers (the 201 file-only rows are listed for sampling); (4) the 13 P3/P4 summary rows import as `milestone` items of their phase.
