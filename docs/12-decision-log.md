## 2026-10-27 / 2026-10-28 · Founding brief (owner instruction)

- **T1 (owner, 2026-10-27).** "Create a new task dashboard tool for Lucid and move our development operation to run through it." Tasks carry everything needed to understand and build them (context, technical data, infrastructure), what is expected (definition of done, mocks, criteria) and the actual result, compared easily; a comment area for feedback before, during and after, which can update the task; dependencies both ways; human tasks (accounts, cards, testing, feedback, decisions); all tasks tracked and updated when done; card view collapsible to line view; filtering, time tracking, issues (support, errors, bugs, system); a unified company tracking system. → `docs/01` §A–§B, `docs/02` §4–§5.
- **T2 (owner).** Embedded AI with model choice including Fable; "tell it what I want and it does it": follow up, reminders, emails to users about tasks that concern them, notifications through the system. Start without SSO; Google SSO is the first task in the system. → `docs/02` §7–§8, `docs/11` LT-0001.
- **T3 (owner).** "Translate (and in the process evaluate) all the work that has been done." The checklist is replaced; a live report of what any agent is working on, "I don't want over reporting, but I do want to track where things stand." → `docs/10`, `docs/02` §5.6, `docs/08` §5.
- **T4 (owner).** A Claude agentic framework with a full modern chat; access to task data, codebase, documents, everything; an in-memory RAG learning from appfront's methods (not its code). Final and actual work is always done by the Claude Code coordinator (Fable, or Opus when context is short); answers, assistance and task updates by the embedded AI. **Working principle everywhere:** anything a user can do in the interface, the AI can do on their behalf. Secure storage and transport for API keys and the like through the chat and the app in dedicated windows. Use Lucid Chat's theming; must work well on a PC and on mobile; testing included and properly executed. → `docs/00` principles 2, 9, 11; `docs/06`; `docs/07` §5; `docs/09`; `docs/research/`.
- **T5 (owner).** The name is **Lucid Total**; a separate project in a separate repository (`nightdweller11/lucid-total`), in its own folder on the machine, not inside the Lucid Chat area. "In the end we'll even sell Lucid Total." It will also be wired into the Lucid Chat app through its API: messages like "you need to call the investor to set a meeting" and "these employees aren't doing well". → `docs/01` §J, §E (UC-E4 phrased as workload signals shown as help), §G; `docs/08` §6.
- **T6 (owner, Hebrew brief, translated).** "A company-wide task board with everything that happens, goals, who is handling what, all deliverables connected to the task, dependencies, schedules where relevant, what is stuck and on what. The wet dream of every company. Integrated AI that knows everything that happens, answers and checks status. Everything transparent; connected to email, to everything. Tasks get closed over the board. Working conversations directly with it in a meeting, with decisions to execute. Things happen as you ask for them." → `docs/01` §A, §C (UC-C6), §D, §E (UC-E3), §G.
- **T7 (owner, 2026-10-28).** Grouping into higher-level groups, contexts and domains; things in more than one group (dependencies across domains: marketing waits for version X); drill into categories, then epics/projects, like zooming in and out of a map; a natural, coherent arrangement "more like a map", modified by the perspective of the viewer (CMO: marketing view; CTO: R&D view) and by the meeting's subject; tasks surfaced and prioritised per viewer. APIs into all the organisation's systems, replacing many. Lucid Total represents the company from the smallest detail to the highest goal and manages tasks, assignments, notifications and progress for everyone. Decisions implemented quickly, even big ones ("focus on Europe": compliance first, marketing budget, Europe attention for everyone, the rest maintained); strategy changes disseminated; who can do what managed in a flat organisation; anyone can suggest; prediction and transparency of change (small and large). The map: semi-physical space, dynamic surface, overlaps; inspirations from mapping and data presentation tools; coherent and easy; all functionality AI-driven; designed so AI tools and LLMs interact with it easily. → `docs/02` §2, §6; `docs/03`; `docs/08`.
- **T8 (owner, 2026-10-28, added context).** Lucid Total is a company operating system in the full sense: it runs the company, it does work, it manages the company; the goal is for the AI to fully manage the company and to facilitate decision making, taking more of the work over time. Design: Lucid Chat's look and feel, theming and a derived logo in the same visual language; apart from colours and fonts, the controls and look are those of a web-based management system for PC and mobile browsers. "Think deeply on how companies work." → `docs/00` §1, principles 9, 14, 15; `docs/02` §2 (functions, rhythms, flows, decision kinds, resources, feedback, the autonomy ladder); `docs/04-mocks/README.md` §Brand.

## 2026-10-28 · Lead decisions (pending the owner's confirmation)

- **T9 (lead).** Documentation order and set as in `docs/00` §7–§8; the methodology of Lucid Chat (walkthroughs, docs in the same change, lead orchestrates, Opus workers, Fable for core and security work, Railway-first, current majors, no GitHub Actions) is inherited verbatim.
- **T10 (lead).** Stack: TypeScript 6 / Node 22, Fastify 5, Drizzle + Postgres 18 on Railway, React 19 + Vite, SVG map with server-computed scenes, in-memory hybrid retrieval with a local embedding model, the Claude API through `packages/ai-gateway` (the official TypeScript SDK inside the adapter only), Railway Buckets. No Redis, NATS, vector DB or Kubernetes at the start (`docs/05` §2, §12).
- **T11 (lead).** Secrets travel as end-to-end encrypted envelopes sealed in the browser to recipients' keys; the server stores ciphertext only; the model never sees envelope contents (`docs/07` §5).
- **T12 (lead).** The autonomy ladder (observe · suggest · confirm · inform · run) is a setting per process; defaults for Lucid in `docs/02` §2.7; outbound channels off until enabled, each with a kill-switch.
- **T13 (lead).** The owner's inbox follows Lucid Chat's L425 rule: material decisions only, one at a time, full context and cost in plain words; small things are settings; very small ones the lead decides and logs here.
- **T14 (lead).** Phase order: Phase 0 the board and the coordinator protocol (the checklist replaced), Phase 1 the AI runs the operation, Phase 2 the map and decisions, Phase 3 company-wide, Phase 4 product (`docs/11`).
- **T15 (lead).** Workload signals about people (T5's "these employees aren't doing well") are implemented as explainable work signals shown to the person first and to the role holder as a workload concern, with thresholds as settings and no verdicts about people (UC-E4). Rationale: trust, labour-law exposure in several markets, and the owner's stated goal of helping the work move.
- **T16 (lead).** Model classes `fast` / `standard` / `strongest` / `fable` map to `claude-haiku-5-5` / `claude-sonnet-5-5` / `claude-opus-5-5` / `claude-fable-5-1` in configuration (2026-10 ids); the owner's chat defaults to `strongest`; Fable is enabled per company by the owner.
